# 로그인/비로그인 화면 차이는 우상단 버튼으로만 제한

- **일시**: 2026-05-09
- **상태**: 확정
- **결정자**: @기획 / @디자인 / @개발 합의
- **분류**: product
- **영향 범위**: Login State, Header, Main

## 문제 (Problem)

로그인/비로그인 상태별 화면 차이를 넓게 정의하면 별도 로그인 페이지, 인증 플로우, 사용자별 콘텐츠 분기까지 구현 범위가 확장된다. 이는 Main 화면의 상품 정렬과 상태 검증에 집중하려는 이번 구현 목적과 맞지 않는다.

## 맥락 (Context)

이번 구현에서는 실제 인증 플로우보다 리디자인된 Main 화면과 ShowCase 화면의 구조, 상품 정렬 상태, Header 차이를 검증하는 것이 중요하다. 로그인 상태는 필요한 경우 query param backdoor로 가정할 수 있다.

## 결정 (Decision)

로그인/비로그인 상태에 따른 화면 차이는 우상단 로그인/로그아웃 버튼 외에는 두지 않는다.

별도 로그인 페이지는 이번 구현 범위에 포함하지 않는다. 로그인 상태가 필요한 경우 query param backdoor를 통해 로그인된 상태를 가정한다. 비로그인 상태에서는 기본 기획 순서를 유지한다. 로그인 상태에서는 Product Like Signal이 있는 경우 Main 상품 정렬 보정이 가능하다. ShowCase 화면은 로그인 상태에 따른 정렬 변화를 갖지 않는다.

## 이유 (Rationale)

실제 인증 플로우 구현보다 Main 화면의 상품 정렬 및 화면 상태 검증에 집중하기 위한 결정이다. 우상단 버튼만 달라지도록 제한하면 로그인 상태를 시각적으로 확인할 수 있으면서도, 콘텐츠 구조와 탐색 흐름의 분기 복잡도를 줄일 수 있다.

## 영향 (Impact)

Header의 우상단 버튼은 로그인 상태에 따라 달라질 수 있다. Main 콘텐츠 전체는 로그인/비로그인 상태에 따라 별도로 재구성하지 않는다. ShowCase는 로그인 상태와 무관하게 동일한 섹션 구조와 정렬을 유지한다. query param backdoor는 실제 인증을 대체하는 구현 편의 장치로만 사용한다.

## 대안 (Alternatives)

- 별도 로그인 페이지 구현
- 로그인/비로그인에 따라 Main 콘텐츠 전체를 다르게 구성
- 로그인 사용자에게만 ShowCase 개인화 적용
- 로그인 상태를 구현하지 않음
