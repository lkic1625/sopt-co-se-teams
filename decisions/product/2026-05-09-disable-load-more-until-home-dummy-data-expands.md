# Main 홈 더보기 버튼은 dummy data 확장 전까지 동작하지 않음

- **일시**: 2026-05-09
- **상태**: 확정
- **결정자**: @기획 / @FE 합의
- **분류**: product
- **영향 범위**: Main, FE, Home Feed, Load More

## 문제 (Problem)

Main 홈에서 무한 스크롤 또는 추가 콘텐츠 로딩 경험을 제공할지 결정해야 한다. 그러나 현재 MVP 범위에서는 더보기로 노출할 만큼 충분한 dummy data가 준비되어 있지 않다.

## 맥락 (Context)

FE에서는 Main 홈 하단에 더보기 버튼을 두는 방식으로 무한 스크롤에 가까운 확장 경험을 구현할 수 있다. 다만 현재 홈 콘텐츠는 고정 dummy data를 사용하며, 콘텐츠 수량이 많지 않다. 이 상태에서 더보기 버튼을 실제로 동작시키면 같은 콘텐츠가 반복되거나 빈 상태 처리가 필요해져 구현과 QA 범위가 불필요하게 커진다.

## 결정 (Decision)

Main 홈에는 더보기 버튼을 둘 수 있지만, 당장은 버튼을 눌러도 추가 콘텐츠가 로딩되지 않도록 구현한다.

더보기 버튼은 향후 dummy data가 충분히 늘어나거나 실제 데이터 연동이 생겼을 때 확장 가능한 UI 진입점으로 유지한다.

## 이유 (Rationale)

현재 데이터 규모에서는 더보기 동작이 사용자에게 실질적인 탐색 가치를 주기 어렵다. 더보기 기능을 완성하려면 추가 데이터 구조, 로딩 상태, 중복 방지, 마지막 페이지 처리, 빈 상태 QA가 필요해진다. MVP에서는 버튼의 위치와 화면 구조만 유지하고 실제 동작은 보류하는 편이 구현 범위와 QA 부담을 줄인다.

## 영향 (Impact)

FE는 더보기 버튼 클릭 시 추가 카드가 렌더링되지 않도록 처리한다. 사용자가 클릭했을 때 화면이 깨지거나 오류가 발생하지 않아야 한다. QA에서는 더보기 버튼 클릭 후 콘텐츠 수, 스크롤 위치, 콘솔 오류 여부를 확인한다.

향후 콘텐츠가 늘어나면 같은 버튼을 실제 페이지네이션, 더보기 로딩, 또는 무한 스크롤 트리거로 전환할 수 있다.

## 대안 (Alternatives)

- 더보기 버튼을 제거
- 더보기 클릭 시 같은 dummy data를 반복 노출
- 처음부터 실제 페이지네이션 또는 무한 스크롤 구현
